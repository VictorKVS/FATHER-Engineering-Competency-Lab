# FATHER Self-Factory Execution Order

## We do not build 101 stages in parallel.

The platform is assembled and verified sequentially.

### Wave 0 — make the factory capable of building FATHER
Stages 000-009.

Goal:
- FATHER is registered as Product FATHER-PLATFORM.
- 000-100 stage model works.
- agent registry works.
- contracts/evidence/gates work.
- stage runner can execute reference/emulation/local/A-B.

### Wave 1 — core chassis
Stages 010-029.

Goal:
minimum platform core + model/tool/memory fabric.

### Wave 2 — agent conveyor
Stages 030-049.

Goal:
agent runtime, workflows, handoffs, artifacts, evidence, traceability.

### Wave 3 — assurance
Stages 050-069.

Goal:
security, testing, evals, A/B, observability.

### Wave 4 — production infrastructure
Stages 070-079.

Goal:
containerization, Kubernetes/CI-CD when justified, rollback, resources.

### Wave 5 — engineering workplace
Stages 080-089.

Goal:
Product Field, editors, overlays, replay and program bindings.

### Wave 6 — certification of FATHER itself
Stages 090-100.

Goal:
full E2E, failure loops, RC freeze, Polygon, release, production evidence.

## Definition of completion

FATHER is not considered ready because its repository contains files.

It is ready only when the complete FATHER-PLATFORM product traverses the factory and reaches Stage 100 with reproducible evidence.
