# Professional Overlay Architecture

## Principle

Layer 1 contains one canonical digital twin.

Specialists do not create competing diagrams. They attach overlays to the same nodes, flows and chains.

Business Analyst
→ System Analyst
→ Architect
→ Data/Knowledge
→ AI/LLM
→ Security
→ QA
→ DevSecOps
→ Optimization
→ Polygon

Each panel can:
- add specialist icons;
- add annotations;
- bind calculations;
- attach documents;
- attach program modules;
- attach tests;
- attach evidence;
- expose specialist metrics;
- mark findings and risks.

## Selectable scope

A user can select:

1. One node
2. One connection
3. A chain
4. A subgraph
5. The whole system

Then choose an action:

ANALYZE
TEST
SIMULATE
MEASURE
COMPARE
A/B
SECURITY CHECK
POLYGON
SHOW EVIDENCE

## Program 00–100 binding

As FATHER modules 00–100 become operational, each module is registered in the model.

Example:

Node: RAG Worker
Programs:
- 14 Memory
- 15 RAG
- 21 Evaluation
- 22 Observability
- 27 CI/CD DevSecOps

The UI must show which real FATHER modules implement or verify the selected element.

## Chain testing

Example selection:

Telegram
→ API Gateway
→ Agent Runtime
→ RAG
→ LLM
→ Telegram Reply

RUN CHAIN TEST executes the relevant node and edge contracts and produces a single evidence-linked result.

This makes the visual model an executable engineering map rather than only documentation.
